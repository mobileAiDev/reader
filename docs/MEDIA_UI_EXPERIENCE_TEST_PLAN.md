# 漫画和听书完整体验测试用例

## 测试边界

- 媒体测试只覆盖 `com.ldp.reader.media.*`、漫画 UI、听书 UI、媒体书架和媒体源资产。
- 小说回归单独验证默认小说搜索、小说详情、小说阅读页，不用媒体书架路径。
- 需要登录、验证码、真人操作、外部浏览器跳转的源一律记为失败源，不提示用户登录。
- App 进程杀死/重启后应恢复媒体书架、当前章节和进度；Android 系统“清除应用数据”会删除本地持久化，不作为可恢复场景。

## 判定口径

- 后端流程通过只证明源解析、目录和内容地址可用；不能替代真机 UI 通过。
- 漫画 UI 通过必须有真实截图或图片加载回调，不能只依赖页码、控件树或 `PhotoView` 节点。
- 听书 UI 通过必须同时看到播放器状态、作品名、章节名、时长和 `media_audio_request_resolved` 可播地址。
- 听书后端 flow 必须校验分集内容唯一性：不同 chapter route 不能解析到同一音频 URL；同一 URL 复用要报 `duplicate_audio_signature`，不能算通过。
- 听书源选择不能只靠目录数量或章节标题；通过源必须来自 `audio_experience`，`chapters_only` 不能作为听书可用源。
- 已知占位音乐、广告音乐或源站固定测试音频即使可播放也必须判为不可用，不能用作真实章节音频。
- 手动下一集/上一集和自然播完自动下一集分开判定；前者通过不能代替后者。
- 未实现入口、需要登录入口、浏览器跳转入口、无效按钮都按核心体验缺口记录。

## 游玩式验收批次

这些用例按真实用户连续体验设计，不只验证单点能否打开。每个批次必须记录 AI App Bridge 的 `state` / `event` 编号，失败也要保留失败原因。

| 编号 | 场景 | 样本 | 执行方式 | 通过线 |
| --- | --- | --- | --- | --- |
| PLAY-COMIC-01 | 漫画追更三连 | `斗破苍穹`、`星辰变`、`完美世界` | 跑 `MediaProbeActivity mode=flow kind=comic`，覆盖长目录、完整目录和预告/公告首章 | 至少 2 本通过；失败必须有 `detail_empty`、图片数为 0 或源不可读分类 |
| PLAY-COMIC-02 | 阅读页连续切话 | `斗破苍穹` 或 `斗罗大陆` | 从真实章节 route 打开阅读页，点下一话、上一话，检查页码从 `1 / N` 开始 | 章节标题和页码随切话变化，不能继承上一话末页页码 |
| PLAY-COMIC-03 | 尾页边界玩法 | `斗破苍穹`、`元尊` | 滚到章节尾页，记录 `media_comic_pages_resolved.count` 和末图 `media_comic_image_load` | 最后一张加载状态明确；加载中不抢跑，失败不永久卡死 |
| PLAY-AUDIO-01 | 短集马拉松 | `斗罗大陆|网文之王|再铸辉煌` | 从 `第000集` 播到自然结束，等待自动切到 `第001集_斗罗大陆` | 出现 `media_audio_auto_next`，新旧 URL token 和时长都不同，自动继续播放后能暂停 |
| PLAY-AUDIO-02 | 长书完整闭环 | `有声小说三体` | 抽中间集做播放/暂停、上一集/下一集、拖动、快进/快退、悬浮条返回 | 标题、章节、进度和播放态一致；悬浮条返回不重新从 0 开始 |
| PLAY-AUDIO-03 | 末集结束 | `有声小说三体` 末集 | 播到自然结束或拖到结尾附近等待结束 | 出现 `state_ended_no_next` 和 `playing_false`，不越界到不存在的下一集 |
| PLAY-AUDIO-04 | 坏源识别 | `庆余年`、`明朝那些事儿` | 跑 audio flow，观察源选择和 route reject 事件 | 重复音频必须为 `duplicate_audio_signature`，不能进入通过样本 |
| PLAY-AUDIO-05 | 定时和迷你播放器恢复 | `斗罗大陆|网文之王|再铸辉煌` | 播放健康分集，点 `定时` 后回书架；在悬浮条暂停，再点播放恢复；最后用服务 action 取消定时 | `media_audio_sleep_timer` 先为 `state_scheduled_minutes_15`，回书架后仍存在；悬浮条暂停出现 `playing_false`，恢复出现 `media_audio_service_reuse` 和 `playing_true`；收尾为 `state_off_minutes_0` |
| PLAY-RECOVER-01 | 书架/悬浮恢复 | `三体` 或 `斗罗大陆` | 播放后回首页，点悬浮条返回；必要时 force-stop 后从书架恢复 | 作品名、章节名、进度、暂停/播放状态不丢 |
| PLAY-NOVEL-01 | 小说不回归 | `诡秘之主`、书架小说 | 默认小说搜索、详情、阅读页、书架进入阅读页 | 仍走小说 `BookDetailActivity` / `ReadActivity`，正文可见 |

## 漫画用例

1. 搜索 5 到 10 本漫画，覆盖不同源和不同目录规模。
2. 每本进入详情页，验证封面、标题、作者/更新信息、简介、目录数量。
3. 每本点击“加入书架”，返回首页确认媒体书架出现漫画卡片。
4. 每本打开首章、随机中间章、尾部附近章节，至少确认 2 到 3 张真实漫画图片可见。
5. 在阅读页点击下一话、上一话，确认标题和页码随章节切换，不能回到空页或目录失败。
6. 每本至少抽一个章节滚到最后一张，核对 `media_comic_pages_resolved.count`、最后一张 `media_comic_image_load position=count` 和 UI 页码三者一致。
7. 末页加载失败和末页还在加载中要分开记录：加载中不能抢跑下一话；失败进入终态后不能把用户永久锁在本话，但该章节仍按图片失败记录。
8. 从章节末页触发下一话，目标章节必须从 `1 / N` 开始，不能把上一话页码 clamp 到目标章节末页。
9. 拖动页码进度条到中间页，返回书架后从媒体书架进入，应恢复到同一章节和对应页附近。
10. 杀死 App 进程并重启，从媒体书架进入同一本漫画，应恢复 route、章节和页码，不依赖重新搜索。
11. 检查目录按钮、正序/倒序、夜间、护眼、横竖翻页、横屏按钮不会遮挡内容或失效。
12. 真机验收必须保存截图或像素证据；只看到 `PhotoView`、页码或控件树节点不算通过，因为图片加载失败时也可能存在这些节点。

## 听书用例

1. 搜索 5 到 10 本听书内容，覆盖直接音频 URL、页面解析 URL、raw 内容解析等形态。
2. 每本进入详情页，验证封面、标题、作者/更新信息、简介、剧集数量。
3. 每本点击“加入书架”，返回首页确认媒体书架出现听书卡片。
4. 每本播放首集、随机中间集、尾部附近集，确认能进入播放器并开始播放。
5. 首集、随机中间集、尾部附近集、相邻上一/下一集的音频 URL 必须记录并比对；不同分集复用同一 URL 时判失败，并记录 `duplicate_audio_signature`。
6. 听书源选择必须记录 `media_route_source_selected.reason_audio_experience`；只出现 `chapters_only`、固定占位音频、样本不可播或重复音频时，该源不能进入播放器验收。
7. 播放页顶部必须同时显示作品名和当前章节名，不能只显示“第几集”。
8. 播放页背景应基于封面取色渲染；唱片外圈不能被左右裁切，摆臂不能被唱片盖住。
9. 播放/暂停按钮应为同一视觉风格，播放三角和暂停双竖条都不能是放大后的尖锐图标。
10. 播放到第 4 章第 10 分钟附近，退回首页，点击听书悬浮条，应回到同一章同一进度附近，不能从 0 开始。
11. 拖动进度条、15 秒快退/快进、播放/暂停、倍速、定时暂停，确认 UI 状态和实际播放一致。
12. 点击下一集、上一集，确认章节切换后能播放、标题更新、音频 URL 更新且上一/下一按钮可用状态正确。
13. 播放自然到结尾时，如果还有下一集，应自动切到下一集并继续播放，并出现 `media_audio_auto_next`；如果是最后一集，应停在播放完成并出现 `state_ended_no_next`，不能越界。
14. 杀死 App 进程并重启，从媒体书架进入同一本听书，应恢复 route、章节、作品名、音频地址和进度，不依赖重新搜索。
15. 悬浮条应显示封面旋转、播放/暂停图标、关闭图标，并支持拖动位置保存。
16. 播放器和详情页不能出现下载、优惠购买、登录跳转、浏览器跳转等无实现或需用户真人操作的入口。

## 小说回归用例

1. 默认进入搜索页仍是小说搜索。
2. 搜索常用小说关键词，确认结果使用小说结果 UI。
3. 进入小说详情页，确认打开的是 `BookDetailActivity`。
4. 点击开始阅读，确认打开 `ReadActivity` 并显示正文。
5. 检查小说内置源资产仍在 `app/src/main/assets/source-engine/book-sources.json`，媒体资产仍在 `app/src/main/assets/media-source-engine/media-sources.json`。
